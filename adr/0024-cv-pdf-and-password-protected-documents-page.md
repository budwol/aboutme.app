# 24. A classic CV PDF and an HTTP-Basic-Auth-protected documents page are generated alongside the Portfolio PDFs

Date: 2026-09-21

## Status

Accepted

## Context

ADR 0010 deliberately named its two-column PDF "Portfolio", not "Lebenslauf"/"Resume", and explicitly deferred "a separate, genuinely compact traditional CV" as a distinct future document. `app-data.json` also didn't yet carry the fields a classic German Lebenslauf needs beyond work history: date/place of birth, marital status, education, languages, a driving license, and interests. Separately, the site needed a way to hand a recruiter a small bundle (the CV plus certificate/reference scans) without publishing it as a normal, navigable, unauthenticated page — the whole site is otherwise a public personal portfolio with no login of any kind.

An email-a-one-time-code flow was considered first, but rejected for now: it needs a real backend (to send email and store/verify a short-lived code), and this site is a pure static export served by nginx with no server-side component at all. A capability-URL scheme (a random token baked into the file name, no password) was implemented next, but rejected once a direct question exposed its actual weakness: any secret needed to grant access has to ship inside the client-rendered page's own JS bundle before it can render an "unlocked" download link, so a technically curious visitor could read the real file URL out of dev tools regardless of whether they ever entered anything — the client can decide what to _show_, never what the server actually _serves_. The design settled on here — a single shared password enforced by nginx's `auth_basic`, entered through a custom in-app overlay rather than the browser's native prompt — is explicitly a stopgap, not equivalent to per-recipient, time-boxed access: everyone who has the password can download everything, indefinitely, until it's rotated by hand.

## Decision

**Data.** `personalDetails` (`birthDate` as ISO `YYYY-MM-DD`, `birthPlace`, `familyStatusDe/En`), `education` (an array shaped like `experience`: `periodDe/En`, plain `institution`, `degreeDe/En`), `languages` (`nameDe/En`/`levelDe/En` pairs), `drivingLicenseDe/En`, and `interestsDe/En` live in a **new, separate file**, `.aboutme/cv-data.json` (bootstrapped from a tracked `cv-data.example.json`, exactly like ADR 0001's existing `app-data.json` handling) — deliberately **not** inside `.aboutme/app-data.json`. That file is copied wholesale, unauthenticated, to the fully public `public/app-data.json` by `sync-web-app-data.cjs`/`init-process.cjs`; anything added to it is readable by any visitor on any page load with zero protection. An early version of this feature put the new fields directly into `app-data.json`, which would have silently published birth date and marital status to the whole internet the moment the site was rebuilt — caught only by a direct question about it, not by anything technical. `sync-web-app-data.cjs` never touches `cv-data.json`; only `generate-cv-pdf.cjs`/`generate-application-package.cjs` read it, straight from `.aboutme/` on the build host.

**CV PDF.** `scripts/generate-cv-pdf.cjs` is a new, independent script (not an addition to `generate-resume-pdf.cjs`) following the ADR 0002 convention, tested from `src/scripts/generateCvPdf/index.test.ts`. It renders `Name_-_Lebenslauf.pdf`/`Name_-_CV.pdf` directly into `public/files/DE/`/`public/files/EN/` (not `public/` root): single column, full document width, plain Helvetica — deliberately closer to `writeAtsResumePdf`'s presentation than the designed Portfolio PDF's sidebar/timeline, since a classic Lebenslauf's whole point is to read as an unambiguous, printable document. Its experience list is **not** capped to the homepage preview length, unlike the Portfolio PDF. It borrows the designed Portfolio PDF's _visual_ details — accent-colored section headings/underlines matching `drawSectionHeading` pixel-for-pixel, an accent rule under the header block, a tinted accent-colored footer, and (unlike an earlier version of this document) a circular header photo and icon-prefixed contact block reusing `prepareEmbeddableAvatar`/`drawVectorIcon`/`formatPhoneNumber` from `generate-resume-pdf.cjs` (reimplemented locally per this file's own established precedent, not imported across the two independent scripts) — while staying strictly single-column and ATS-safe; no sidebar or timeline was added, since that would defeat the point of a plain-text-parseable CV. The photo sits top-right of the header, the classic Lebenslauf placement, sized against whichever is taller: the photo or the name/title/contact text block next to it. The designed CV's footer also links to its own ats companion (`buildAbsoluteUrl`, the same footer link the designed Portfolio PDF already carries) so a reader who wants the plain-text version doesn't have to know its filename by convention.

A "Zertifizierungen"/"Certifications" section (`buildCertificationNames`) renders `data.certificates` — the exact same `{nameDe, nameEn}[]` array the designed Portfolio PDF already shows as a pill list — as its own paragraph, styled the same as the "Sonstiges" section (heading + plain text) but deliberately not folded into it: repeating "Zertifikat"/"Arbeitszeugnis" inside "Sonstiges" would have buried a distinct qualification as a third line under Sprachen/Führerschein rather than giving it equal visual weight. It sits between "Sonstiges" and "Interessen" and is skipped entirely when `data.certificates` is empty, same as every other optional CV section.

Once that styling made the CV visually closer to the designed Portfolio, it stopped being the plain "ats" companion Portfolio-ATS is for the Portfolio PDF — so `writeCvPdf` also takes an `{ ats: true }` option, threaded through `drawSectionHeading` and the header/footer accent drawing, that renders `Name_-_Lebenslauf_ATS.pdf`/`Name_-_CV_ATS.pdf`: the exact same content with every accent-colored rule, underline, and footer tint skipped, matching `writeAtsResumePdf`'s plain-black-heading convention. Unlike Portfolio-ATS, this file still lives under `public/files/<DE|EN>/`, not `public/<DE|EN>/` — it carries the same CV-only personal fields (birth date, marital status, ...) as the designed CV, which must never be reachable without `auth_basic` regardless of how plain its styling is.

**Naming: the language lives in the word, not a suffix.** Every fixed document's file name spells out its own language rather than carrying a `_DE`/`_EN` token: `Lebenslauf`/`CV` (`buildCvFileName` in `generate-cv-pdf.cjs`), `Bewerbungsunterlagen`/`ApplicationDocuments` (`buildPackageFileName` in `generate-application-package.cjs`). `Portfolio`/`Portfolio_ATS` (`buildPortfolioFileName` in `generate-resume-pdf.cjs`) is the one exception where the word is identical in both languages — there is nothing left in the name itself to disambiguate DE from EN, so instead every one of these ten files, without exception, now lives inside its own `DE/`/`EN/` subfolder (`public/files/DE/`+`public/files/EN/` for the CV/ZIP; `public/DE/`+`public/EN/` for the Portfolio pair, keeping the existing protected-vs-public split unchanged) rather than sitting flat with a suffix. `document-sizes.json` (below) is keyed by these same folder-qualified pathnames.

Its `drawRow` helper (a narrow left "period" column beside a wide right "content" column, the standard German Lebenslauf layout) measures both columns' full height up front and calls `doc.addPage()` itself before drawing anything, rather than letting pdfkit's own auto page-break fire mid-row. An earlier version let each column auto-flow independently; a page break firing mid-way through only one of the two columns left their cursors pointing at two different pages, silently tearing rows apart into a trail of near-blank pages — the same class of hazard ADR 0010 documented for the two-column Portfolio PDF, showing up again in a single-column-but-two-text-blocks-per-row layout.

**Application package ZIPs.** `scripts/generate-application-package.cjs` composes `generateCvPdf` and `generateResumePdf`, then writes **two** language-specific ZIPs — `public/files/DE/Name_-_Bewerbungsunterlagen.zip` and `public/files/EN/Name_-_ApplicationDocuments.zip` — rather than one shared archive. Each bundles that language's full fixed document set — CV, CV-ATS, designed Portfolio, and Portfolio-ATS, every one of them under the exact same name it has as its own standalone download (`buildCvFileName`/`buildPortfolioFileName`, not a generic `CV.pdf`/`Portfolio-ATS.pdf` placeholder, so a file pulled out of the zip is still self-identifying on its own) — plus every file under `.aboutme/secrets/{Zertifikate,Arbeitszeugnisse,Zeugnisse}/` (flat, non-recursive per category, each kept as its own subfolder inside the ZIP, identical in both ZIPs since none of them are language-specific). An earlier version left the designed Portfolio and the CV's own ATS companion out of the zip entirely, reasoning that the designed Portfolio is already public elsewhere (`src/utils/resumePdfUrl`) — reversed once it became clear a recruiter forwarded the whole zip as _the_ application package and expected it to be complete on its own, not a partial set they'd have to top up from the documents page. A single shared ZIP was tried first but rejected: a recruiter who asked for the English documents would otherwise have to sift out the German ones bundled alongside them. No ZIP library was added as a dependency — ADR 0002 keeps build scripts dependency-light, and Node's built-in `zlib` already provides DEFLATE; the ZIP container format itself (local file headers, a central directory, an end-of-central-directory record) is small enough to write and verify byte-for-byte in `src/scripts/generateApplicationPackage/index.test.ts`. File names under `public/files/` are plain and deterministic (no random token): the real access control is `auth_basic`, so hiding the name buys nothing. Every entry name is written as UTF-8 with the ZIP format's language-encoding flag (general purpose bit flag bit 11) explicitly set, so real umlaut-bearing scan file names (`"...Teilnahmebestätigung..."`) round-trip correctly through a spec-compliant reader instead of decoding as legacy CP437 and garbling.

**Portfolio and Portfolio-ATS as standalone downloads.** Both the designed, two-column Portfolio PDF and its plain, single-column "ATS" variant (ADR 0011) — previously generated but, before this, either only reachable from the contact footer/drawer menu (the designed one) or not linked anywhere on the site at all (the ATS one) — are now also listed as their own downloadable entries on the documents page (`portfolioDe`/`portfolioEn`/`portfolioAtsDe`/`portfolioAtsEn` in `src/utils/documentsManifest`), alongside the equivalent CV pair, in addition to the designed CV and Portfolio-ATS being bundled inside each language's ZIP. `portfolioDe/En` reuses `getResumePdfUrl` (`src/utils/resumePdfUrl`) rather than duplicating its URL-building logic. Unlike the CV PDFs and ZIPs, all four of these files live in `public/DE/`/`public/EN/`, not `public/files/<DE|EN>/`: they're the exact same, already-public downloads linked elsewhere on the site, so listing them here adds convenience, not protection, and they're cache-busted with `getVersionedLocalAssetUrl` like any other root-level asset instead of relying on `/files/`'s `Cache-Control: no-store`.

**The access control.** `scripts/init-process.cjs` generates a genuinely random 32-character password (`generateDocumentsPassword`: a leading `!`, then 31 alphanumeric characters guaranteed by construction — not left to chance — to include at least one uppercase letter, one lowercase letter, and one digit, via `crypto.randomInt`), persisted to `.aboutme/secrets/documents-password.txt` (gitignored, like the rest of `.aboutme/`) so it survives rebuilds instead of invalidating an already-shared password on every `npm run init`. `buildHtpasswdLine` hashes it with nginx's `{SHA}` scheme (`base64(SHA-1(password))`, RFC 2307) using only Node's built-in `crypto` — no `htpasswd` CLI, no new dependency — and writes `nginx/.htpasswd` (gitignored, generated, `COPY`'d into the Docker image in `Dockerfile`). `nginx/site.conf`'s `/files/` location carries `auth_basic "Restricted"; auth_basic_user_file /etc/nginx/.htpasswd;`, a fixed non-secret username (`documents` — with Basic Auth all the secrecy lives in the password), `Cache-Control: no-store`, `autoindex off`, and `try_files $uri =404` so a wrong guess returns a plain 404 rather than the SPA shell.

**`location ^~ /files/`, not `location /files/`.** This is the one detail in this whole feature that unit tests alone did not catch. nginx always prefers a matching _regex_ location over a plain _prefix_ location, no matter how specific the prefix is — regardless of declaration order. The existing generic asset-caching rule, `location ~* \.(js|css|png|...|pdf)$`, matches `.pdf` files anywhere on the site, including under `/files/`. Without the `^~` prefix modifier, a request for a CV PDF matched that unrelated regex location instead of the `auth_basic`-protected one and was served with **zero authentication** — verified by building the real Docker image and curling it with no credentials, not caught by any config-string assertion. `^~ /files/` tells nginx to stop checking regex locations entirely once this prefix is the longest match, regardless of file extension. `src/scripts/initProcess/index.test.ts` has a dedicated regression test for this, but the real lesson generalizes: nginx location-matching bugs of this shape are invisible to a test that only inspects the generated config text — they require actually building the image and sending a request.

**Frontend.** A new route, `downloads` (`/bewerbungsunterlagen` / `/application-documents`), renders `WnaDownloadsRoute`. It is registered in `wnaRouteTable`/`wnaNavigationRoutes` like any other route — reachable by direct URL — but has no entry anywhere in `WnaNavigationList`/`WnaMenuRoute`. The whole site already sends `X-Robots-Tag: noindex, nofollow, ...` and a blanket `robots.txt` disallow, so it isn't crawlable either. The page shows a password field and an "Entsperren"/"Unlock" button rather than the browser's native Basic Auth dialog: submitting it performs a `fetch(firstDocumentUrl, { method: "HEAD", headers: { Authorization: "Basic " + btoa("documents:" + password) } })`, and a `200` response is itself the proof the password was correct — there is nothing else to verify client-side, since the server is the actual gate. On success the `Authorization` header value is kept in `sessionStorage` (not `localStorage`: a closed tab or a different browser asks again) and reused for each per-document download, which goes through `fetch()` + `Blob` + a synthetic `<a download>` click (`triggerBlobDownload`) rather than a plain `<a href>`, specifically so the request carries an explicit header instead of relying on the browser's own native credential prompt/cache. A `401` on any later download clears the stored header and re-locks the page, since it means the password was rotated since the session started. `src/utils/documentsManifest` builds all ten document URLs (ZIP, CV, CV-ATS, Portfolio, Portfolio-ATS, times two languages) from `appData.profile.name` via a newly extracted, shared `src/utils/slugifyName` (previously duplicated inline inside `src/utils/resumePdfUrl`), grouped German-first so `documents[0]` is always a real `/files/`-protected URL for the unlock check to verify against.

Once unlocked, the ten documents render as two flag-marked `WnaSurfaceCard`s — 🇩🇪 and 🇬🇧 — stacked below the intro card, each holding that language's ZIP, CV, CV-ATS, Portfolio, and Portfolio-ATS row (`LANGUAGE_SECTIONS` in `WnaDownloadsRoute`), rather than one flat list: a shared list mixing both languages made it harder to tell at a glance which document was which, and made the single mixed ZIP (superseded above) look like the only "complete" download.

**15-minute inactivity auto-lock.** An unlocked session also re-locks itself after 15 minutes with no download activity, even within the same tab (where it would otherwise stay unlocked indefinitely per the paragraph above). `markActive()` writes a `Date.now()` timestamp to a second `sessionStorage` key (`wna-documents-auth-last-active`) on every successful unlock and on every download attempt, and a `setTimeout` scheduled for the remaining window clears both stored keys and re-locks when it fires; a page load that finds an existing session recomputes the remaining time (or locks immediately if it's already stale) instead of always granting a fresh 15 minutes. This is explicitly a client-side convenience only, not a second security boundary — the real gate stays `auth_basic`, which has no concept of a session and doesn't care whether this timer ever ran — but it does mean a browser left open and unattended (e.g. a shared/public machine) stops offering one-click re-downloads after a quarter hour. A missing or unreadable timestamp (sessionStorage disabled, or a session persisted before this feature existed) is deliberately treated as "activity just happened," not as "infinitely stale": the alternative would auto-lock every unlock immediately whenever storage can't be read, which is worse than not having the feature.

**Reference/certificate scans, individually linked as well as bundled.** The ZIP's certificate support (above) originally read from `.aboutme/certificates/`, a folder that doesn't actually exist in this deployment — the real scans live in three separate, already-organized folders: `.aboutme/secrets/Zertifikate/`, `.../Arbeitszeugnisse/`, `.../Zeugnisse/` (gitignored, alongside `documents-password.txt`). `generate-application-package.cjs` reads all three (flat, non-recursive per category), keeping each category as its own subfolder inside the ZIP (`Zertifikate/`, `Arbeitszeugnisse/`, `Zeugnisse/`, in that order) rather than flattening them into one `Certificates/` folder. Files sort alphabetically within a category, except `Arbeitszeugnisse`, which sorts in reverse: its file names all share the same `<Name>_-_Arbeitszeugnis_<YYYY-MM-DD>_...` shape, so a plain descending string sort already reads as newest-reference-first, the usual CV convention. The same files are also copied individually into matching subfolders under `public/files/` and listed in a new `public/files/references-manifest.json` (written unconditionally, even when empty) — unlike the fixed CV/Portfolio/ZIP file set, the exact reference files present are deployment-specific data the frontend can't know at build time, so `WnaDownloadsRoute` fetches this manifest at runtime (`src/utils/referenceDocumentsManifest`) instead and renders one additional card per non-empty category, reusing the same `WnaNavigationItem` row style as the fixed documents. Each entry's `label` is derived from its file name (`buildReferenceDocumentLabel`: strips the shared `<Name>_-_` prefix, then the category's own word — `"Zertifikat"` for `Zertifikate`, `"Arbeitszeugnis"` for `Arbeitszeugnisse` — since that word only repeats what the card's own heading already says, and finally turns the remaining underscores into spaces, e.g. `"Zertifikat_AutoCAD.pdf"` → `"AutoCAD"`) rather than shown as a raw file name. `writeReferenceDocuments` fully replaces each category's `public/files/` subfolder (`fs.rmSync(..., { recursive: true, force: true })`) before repopulating it, rather than only ever adding/overwriting files by name: a scan removed (or renamed) in `.aboutme/secrets/` otherwise dropped out of `references-manifest.json` immediately but left its old copy sitting under `public/files/` indefinitely, since nothing else ever deleted it.

Writing real file names with German umlauts (`"...Teilnahmebestätigung..."`) through the ZIP writer surfaced a genuine, previously-latent bug: `createZipArchive` encoded entry names as UTF-8 bytes but never set the ZIP format's "language encoding flag" (general purpose bit flag bit 11 / `0x0800`), so a spec-compliant reader (Python's `zipfile`, Windows Explorer, strict-mode 7-Zip — not `unzip`'s more lenient default) decoded those bytes as legacy CP437 and garbled every non-ASCII character. Fixed by setting that bit on both the local file header and the central directory header; regression-tested by reading the raw flag bytes back out of a generated archive with a non-ASCII name.

**Per-document file size.** Every row on the documents page — fixed and reference alike — shows its file size next to its label (`"Lebenslauf (245 KB)"`). Reference-document sizes are inline on their own manifest entries (`size`, in bytes — free, since `generate-application-package.cjs` already holds each file's buffer when building `references-manifest.json`). The fixed CV/Portfolio/ZIP set has no such per-entry manifest of its own (`src/utils/documentsManifest` only ever builds URLs from the profile name, never touches the filesystem), so a separate flat `{url: sizeInBytes}` map, `public/files/document-sizes.json`, is written alongside it, covering all ten fixed documents including the two Portfolio/Portfolio-ATS files that live in `public/` root rather than `public/files/`. Its keys are plain pathnames with no query string; the frontend strips the Portfolio URLs' own cache-busting `?v=...` before looking a size up (`lookupDocumentSize`), so the size manifest itself never needs to know the current deploy version. Both manifests are fetched together (`Promise.all`) the same place `references-manifest.json` already was, sharing its 401-triggers-relock handling.

**Expandable/collapsible document cards, ordered by current language.** Each card (both language cards and each reference-document category card) starts as a collapsed or expanded `WnaNavigationItem`-style row group behind a clickable heading (title left-aligned, a `chevron-up` icon on the right that rotates 180° when collapsed) rather than always showing every row at once — with ten-plus fixed documents plus a variable number of reference scans, an always-expanded page got long fast. The language card matching the site's current UI language (`getNavigationLang()`) starts expanded; the other starts collapsed, on the reasoning that a visitor reading the German site most likely wants the German documents first. The card _order_ follows the same logic: the current-language card renders first, then the reference-document categories (`Zertifikate`, `Arbeitszeugnisse`, `Zeugnisse`, in that fixed order, always collapsed), then the other language card last — rather than always German-then-English regardless of which language the visitor is actually reading in.

## Consequences

- This is a single shared secret, not per-recipient or time-boxed access: anyone who has the password can download everything, indefinitely, until `.aboutme/secrets/documents-password.txt` is deleted and regenerated — which immediately locks out everyone, not just one leaked recipient. An email+one-time-code flow would fix this but needs a real backend this static site doesn't have; that remains a deliberately deferred follow-up, not implemented here.
- HTTP Basic Auth only protects the credential in transit if TLS actually terminates in front of nginx end-to-end (the container itself only speaks plain HTTP on 8080) — this relies on whatever sits in front of the deployed container providing that, same as the existing `Strict-Transport-Security` header already assumes.
- `nginx/.htpasswd`'s SHA-1 digest ends up baked into the Docker image layer; if that image is ever pushed to a non-private registry, the digest is retrievable for offline attack (computationally infeasible against 32 random characters, but present).
- `scripts/generate-cv-pdf.cjs`, `scripts/generate-application-package.cjs`, and the password/`.htpasswd` generation in `scripts/init-process.cjs` are, like all `scripts/*.cjs` build tools, outside the Istanbul `coverageThreshold` gate (ADR 0013 scopes that to `src/**/*.{ts,tsx}`) — verified by their own dedicated Jest suites instead, including pagination, malformed-password-file recovery, and ZIP-structural-validity edge cases. Everything under `src/**/*.{ts,tsx}` this feature touches (`WnaDownloadsRoute`, `documentsManifest`, `slugifyName`) is covered by the enforced 100% gate as usual.
- Reference/certificate scans are language-agnostic and get duplicated into both the DE and EN ZIP, so `public/files/` holds three copies of every scan (once per ZIP, plus once more for the individual-download copy under its own category subfolder) rather than one shared copy referenced by all three — a deliberate size-for-simplicity tradeoff (no cross-archive references exist in the ZIP format without a second download step) that only matters once a meaningful number of scans accumulate.
- `document-sizes.json` and `references-manifest.json` are both served under `/files/` and therefore both `auth_basic`-protected, even though a file size or a reference document's prettified label alone isn't particularly sensitive on its own — simpler than carving out a separate unauthenticated path for two small JSON files.
- A geographic (Germany-only) access restriction was discussed and deliberately deferred: it would need nginx's GeoIP2 module plus a MaxMind GeoLite2 database and license key (an external account/credential to obtain and keep updated), for a control that's trivially bypassed by any VPN and risks false-positive-blocking legitimate access from abroad. `auth_basic` and the unlisted route remain the two layers actually in place; GeoIP would only ever have been a bot/opportunistic-traffic filter on top.
